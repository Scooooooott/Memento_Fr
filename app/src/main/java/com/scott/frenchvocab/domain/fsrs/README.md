# FSRS provenance and product policy

This Kotlin implementation ports Open Spaced Repetition's **ts-fsrs v5.4.2**, FSRS-6.0, released 2026-09-01 (release commit `bb71e35`). It uses the published default 21 parameters, `request_retention=0.90`, `enable_fuzz=false`, and `enable_short_term=false` (`LongTermScheduler`). The MIT notice is in `THIRD_PARTY_LICENSE.txt`.

All ratings schedule a later daily review; **Again is due no sooner than 24 hours later**, never reinserted into the active queue. New cards initially receive intervals of Again 1, Hard 2, Good 3, Easy 8 days, matching the upstream long-term policy. This app deliberately does not use minute-based learning/relearning steps. Each review becomes state REVIEW. Lapses increment only when an already-reviewed card receives Again.

The elapsed-days calculation preserves upstream UTC calendar-day boundaries. Due times use absolute 24-hour units. Daily new-word quotas and activity statistics use the device's local calendar day of each actual rating, stored in the review log. An unfinished session survives midnight unchanged; its remaining new words count on the day they are rated, and a following session receives only the remaining daily allowance. Settings and queue order are snapshotted when the session starts.

Numerical parity includes upstream 8-decimal rounding, difficulty damping, failure stability cap and interval ordering. Upstream's ordering can yield an Easy interval of 36503 days when all states reach the 36500-day cap; the port preserves that behavior. App-side guards reject invalid memory states, negative timestamps and overflow; repository clock rollback uses the previous review time rather than corrupting the schedule.

JVM fixtures compare the port with outputs generated by the unmodified published `ts-fsrs@5.4.2` package. No optimization/personalized weights are included in this development version.
